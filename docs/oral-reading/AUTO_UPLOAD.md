# Automatic reading upload and assistance context — 12 October 2026

The parent could select a recording on the Mac but Send was disabled. The prior screen disabled it whenever pairing, service readiness or connectivity failed, and offered no connection control on the recording page. The actual Mac message was not available to inspect. The replacement keeps an unsent audio File and its passage/context in IndexedDB, restores it after reload, and starts assessment automatically once this browser is connected. Each browser still needs its own private pairing; no game snapshot is sent by the reading page and the iPad save remains unchanged.

Choosing a file or stopping capture starts automatic assessment when a passage is present. MP4/WebM are explicitly accepted in addition to existing formats, subject to browser decoding. During recognition, form controls are locked. When complete, the optional comprehension answer, assistance/reread flags and helped-word notes can be edited and synced through authenticated `/oral/context`, without another Azure call. Context updates preserve word timings, alignment and numeric evidence; assisted results must not be interpreted as independent fluency. Helped words are parent observations, not automatic speaker attribution. Assisted practice is the default and can be unchecked for a genuinely independent attempt.

Unpaired/offline recordings stay local until connection; completed reports retain the existing durable retry queue. An interrupted assessment is not silently retried after reload because its billing/result outcome is uncertain; Retry upload makes that explicit. New context has its own local retry queue. Audio recovery is browser-local, not permanent cloud storage, and is removed once reports sync. The same two-minute microphone cap remains; recordings stopped before the passage ends still need the parent to distinguish unread endings from omissions. This release does not add diarization or claim that Azure separates parent and child speech.

Validation: 415 unit/backend tests and 123 UI groups pass. Browser tests cover actual MediaRecorder with synthetic audio, automatic submission, unpaired file recovery after reload, inline connection, failed-report retry without a second assessment, help/comprehension context updates, denied microphone and narrow layout. Backend tests check owner-only context changes, preserving word evidence, duplicate report retries and replacement of old multipart rows.
